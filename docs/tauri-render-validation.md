## 统一入口

```ts
import { validateRenderDocument } from "./render-input";

const result = validateRenderDocument(snapshot.document);
if (result.ok) {
  // result.input.composition.width/height 为正安全整数或 "auto"。
  // result.input.root 是已补默认值、忽略空文字和空容器的独立渲染树。
  // 将 input 交给后续 Engine；warnings 交给界面展示。
} else {
  // errors 包含 code、path、message，以及可取得的 moduleId；阻止本次渲染。
  // warnings 仍会返回；源文档可以继续编辑、保存。
}
```

入口接受 `unknown`，不能因为 Rust 成功解码或 TS 静态类型存在就跳过校验。错误路径示例为 `$.modules[0].style.fontSize`。返回值通过 `ok` 区分成功与失败，失败不提供可供绘制的部分结果。

实现分为 `document.ts`（文档、模块、网格）、`style.ts`（外观、文字、背景）、`processors.ts`（调用声明）、`validation.ts`（公共字段检查）、`defaults.ts`（默认常量）及 `types.ts`（校验后的只读输入）。图片 `fit` 和字体默认值沿用 `image.ts`、`font.ts`。树遍历使用显式栈，不依赖递归调用栈。

当前只校验参数，不读取图片、不查询字体是否可用、不执行处理函数、不测量或绘制 Canvas。图片处理声明的结构和非空标识在此检查；函数注册、参数业务约束、执行及输出检查仍由既有处理链负责。其不透明参数沿用原有任意 JSON 值协议，不由通用字段校验器解释。

## 职责与错误处理

- Rust 负责可靠读写和文档会话，不承担渲染参数的业务枚举校验。现有 Serde 结构解码要求仍然存在；本文不修改 Rust 实现。
- TS 在渲染前检查字符串是否属于对应枚举，以及参数类型、范围和必填项。
- 非法参数报告具体字段路径和原因，阻止本次渲染。
- 渲染参数不允许显式 `null`。省略可选字段才使用默认值，不能通过 `null` 请求默认值。
- 默认值及自适应计算只作用于渲染输入，不回写 JSON 或修改原始文档。
- `style` 等渲染参数对象中的未知字段保留原值、发出警告，不参与当前版本渲染；不因未知字段阻止出图。扩展元数据仍保留，不按未知渲染参数报警告。
- `composition`、`style`、`style.border`、`style.background` 按支持的参数列表检查未知字段。文档、模块和放置记录上的普通扩展元数据不按未知参数报警告；明确识别的旧渲染字段另行警告。未支持的 `zIndex`、`rowGap`、`columnGap`、旧偏移等参数不参与渲染。

## UI 可调参数

已确认的可配置布局、尺寸及文字参数应支持在后续 UI 中调节。默认值集中定义，仅在字段省略时生效；用户显式配置优先，并通过既有文档编辑流程保存到 JSON。

UI 参数输入与预览、导出复用同一套 TS 校验和默认值规则。计算结果可以用于展示，用户通过修改源参数调整布局；本文当前不表示对应 UI 控件已经实现。

## 模块尺寸与自然布局

- 可渲染文档统一为单根结构：沿用现有 `modules` 数组，但其中必须且只能有一个根模块。根可以是叶子模块或 `group`；需要多个内容时，通过根 `group` 的 `layout` 和 `children` 组织。
- 单根约束由 TS 渲染校验执行，不在 Rust 增加业务校验；文档能够读写不代表已经满足可渲染条件。无需为多个无父模块另设画布排列规则。
- 叶子模块（`text`、`image`、`rect`）必须显式指定 `width` 和 `height`；缺失时报错。
- 叶子宽高表示模块的布局区域；区域内部的文字排版和图片适配按后文各自的规则处理。
- 子模块保留自己的尺寸，不由父布局覆盖；撤销此前“子模块宽度始终服从父布局”的讨论方案。
- `group` 自身的尺寸始终由内部布局计算，当前不提供手动指定容器布局宽高的能力。
- 网格每列取该列子模块的最大宽度，每行取该行子模块的最大高度。嵌套容器先计算自身尺寸，再作为整体参与父级计算。
- 完全没有子模块的行、列在渲染时自动忽略，实际使用的行列按原顺序排列，不为被忽略的行列保留尺寸或额外间距。例如 `[2, 2]` 的第二列为空时，按一列渲染。
- 单个空单元格不导致整行或整列被删除：只有整行、整列均无子模块时才忽略该行、列。校验坐标范围仍以原始 `layout` 为准；折叠只影响渲染，不改写 JSON 中的 `layout`、`position`。
- `children` 省略或为空的 `group` 在渲染时忽略，不占尺寸、内边距或元素间距。嵌套时，忽略空容器后再判断父级的有效行列和内容。
- 如果根模块因此为空，提示“无可渲染内容”，暂不生成 PNG；文档仍可编辑、读写和保存，不自动删除空容器或修改原始 JSON。
- 子模块小于所在单元格时，保持自身宽高，默认水平、垂直居中。

## 默认间距

第一版使用两个统一数值：

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `padding` | 容器四边统一的内边距 | 24 像素 |
| `gap` | 相邻行、相邻列之间统一的间距 | 24 像素 |

自然布局计算方式：

```text
宽度 = 各列宽度之和 + (列数 - 1) × gap + 2 × padding + 2 × borderWidth
高度 = 各行高度之和 + (行数 - 1) × gap + 2 × padding + 2 × borderWidth
```

上式中的行数、列数指忽略完全空的行列后的有效数量；`borderWidth` 为当前容器的边框宽度，未启用时为 `0`。空容器直接忽略，不套用该公式。

嵌套容器的内边距和边框已计入该容器尺寸，父级将它作为整体处理。

默认值已在 TS 中集中定义，容器间距见 `RENDER_DEFAULTS.groupPadding` 和 `RENDER_DEFAULTS.groupGap`，方便后续调整。

## 尺寸数值

- JSON 中显式填写的叶子宽高、顶层输出宽高必须为正安全整数；顶层输出另允许 `"auto"`。
- 最终 PNG 不额外设置固定业务尺寸上限。Engine 负责检查实际 Canvas 能力；尺寸不支持或无法创建绘制目标时报告错误，停止本次出图。安全整数要求属于 JS 数值精度限制，不代表任意尺寸都能由 Canvas 生成。
- JSON 中的 `padding`、`gap` 必须为非负整数，允许 `0`。
- 不接纳小数作为上述参数输入。
- 整数输入经过居中、间距分配或等比缩放仍可能产生小数。按本轮问题范围，JSON 输入仍要求整数，计算后的像素坐标和尺寸最多保留一位小数。
- 中间运算保留精度，在生成布局结果时统一处理小数位，避免逐步取整积累误差；缩放系数不按像素值限制为一位小数。
- 最终 PNG 宽高必须为整数；自适应计算结果带小数时向上取整，避免裁掉边缘内容。显式指定的整数输出尺寸保持不变。
- 展示实际输出尺寸，方便用户按需手动调整参数；不为消除小数或适配输出而改写原始 JSON。

## 文字参数

| 参数 | 省略时的默认值 | 显式输入要求 |
| --- | --- | --- |
| `style.fontSize` | 24px | 正整数 |
| `style.color` | `#000000`（黑色） | `#RRGGBB` 或 `#RRGGBBAA`，允许大小写 |
| `style.align` | `"left"`（左对齐） | `"left"`、`"center"`、`"right"` |
| `style.verticalAlign` | `"center"`（垂直居中） | `"top"`、`"center"`、`"bottom"` |
| `style.bold` | `false`（不加粗） | 布尔值 `true` 或 `false` |
| `style.lineHeight` | `fontSize × 1.2`；默认字号下为 28.8px | 正整数像素值；省略时的计算结果允许保留一位小数 |
| `style.wrap` | `true`（开启自动换行，沿用此前确认的默认行为） | 布尔值 `true` 或 `false` |
| `style.padding` | 0px | 非负整数；文字自身的四边统一内边距，与容器内边距独立 |
| `style.fontFamily` | `"sans-serif"`（系统无衬线字体） | 非空字符串；可从 Rust 枚举的本地字体列表选择 |

文字模块仍必须显式指定固定 `width`、`height`，字号过大或换行不会撑高模块及其父容器；不采用曾提出的文字高度省略或 `"auto"` 方案。

`text` 为空字符串，或仅包含空格、制表符、换行等空白字符时，渲染时忽略整个文字模块，不占布局空间；由此产生的空行、空列及空容器沿用前述忽略规则。只判断是否全为空白，不改写原始文本或删除文档节点。

自动换行是独立开关，开启时按可用宽度换行，关闭时不自动换行；仍保留原文中的显式换行。文字在扣除自身内边距的内容区域排版，超出该区域的部分不渲染，不自动缩小字号或扩张模块。

文字在自身模块内部的水平对齐、垂直对齐和内边距可独立设置，与模块在父网格单元格中的居中位置分开处理。文字内边距独立于容器的 `padding`。

扣除文字内边距和边框后的内容宽、高必须都大于 `0`，即 `width - 2 × (style.padding + borderWidth) > 0` 且 `height - 2 × (style.padding + borderWidth) > 0`；未启用边框时 `borderWidth = 0`。否则报参数冲突并阻止渲染，提示调整内边距、边框或模块尺寸。

合法参数下文字超出内容区域时直接裁剪，不提示、不产生警告，也不阻止出图。此前极端布局不足导致整体等比缩小的情况仍按约定警告，两类处理分开。

纯色参数统一接受六位或八位十六进制格式，包括文字及后续背景、边框的纯色值；八位格式末两位表示透明度。具体颜色和透明度支持用户通过 UI 调整。不接纳短十六进制、颜色名称或 `rgb()` / `hsl()` 等其他写法。

显式指定的 `style.fontFamily` 在当前机器不可用时，回退系统默认 `sans-serif`，继续渲染并警告，提示用户重新选择字体；不改写文档中的原始名称。当前独立解析函数只处理类型及默认值，可用性检测、警告和回退仍需接入后续 Engine。

## 本地素材引用

新 TS 方案只消费用户准备好的本地图片文件，普通图片及图片背景统一使用 `assetPath`。素材准备由用户自行完成，应用只读取最终本地文件。

- 相对路径以图片 JSON 所在目录为基准，也允许绝对本地路径；保留路径原值，不在参数解析时改写或移动文件。
- `assetPath` 省略、为空字符串或仅含空白时，按未选择素材处理，使用警告占位图。
- 显式值必须为字符串，不接纳 `null`、其他类型、NUL 字符或 URI 形式；HTTP、data、file 等 URI 不作为素材路径。
- `resolveLocalImagePath` 已提供类型与路径输入检查，返回路径原值或 `undefined`。目录解析、文件读取与解码仍待 Engine 接入；该函数不判断文件是否存在。
- `assetId`、`assetQuery`、`assetsDir` 和 `assetAliases` 属于旧方案的数据，不再由新 TS 渲染层解析。Rust 可继续保留、读写这些字段；作为旧渲染配置遇到时保留并警告，不自动转换或猜测素材位置。
- 使用旧字段的既有样例仍需按新规则迁移，当前不批量改写。

## 图片参数

图片经过处理链并按 `fit` 适配后，默认在自身内容区域内水平、垂直居中；内部对齐与模块在父网格单元格中的位置分开处理，并支持 UI 调整。

| 参数 | 省略时的默认值 | 显式输入要求 |
| --- | --- | --- |
| `style.align` | `"center"`（水平居中） | `"left"`、`"center"`、`"right"` |
| `style.verticalAlign` | `"center"`（垂直居中） | `"top"`、`"center"`、`"bottom"` |
| `style.padding` | 0px | 非负整数；四边统一内边距，与容器内边距独立 |

图片沿用文字的有效内容区约束：`width - 2 × (style.padding + borderWidth) > 0` 且 `height - 2 × (style.padding + borderWidth) > 0`，否则报参数冲突并阻止渲染。

图片经过 `fit` 适配后，超出自身内容区域的部分按区域边界直接裁剪，不提示，也不改变模块尺寸；适用于 `cover` 铺满或 `height` / `width` 等比适配后另一方向超出的情况。

图片尚未选择素材、没有有效素材引用时，不忽略模块：保留其尺寸和位置，使用内置的“警告：找不到图片”占位图。占位图见 `desktop/src/assets/image-not-found.svg`，TS 通过 `src/render-assets/` 导出的 `IMAGE_NOT_FOUND_ASSET_URL` 获取资源 URL；不将占位图路径写入原始 JSON。

已经指定素材引用，但文件不存在、读取失败或无法解码时，同样保留模块尺寸和位置，使用上述警告占位图继续出图；不改写原始引用。

占位图跳过原素材处理链，以完整居中方式显示，避免警告被裁剪或模糊；当前已提供占位素材和 TS 导出入口，实际替换仍待 Engine 接入。

## 模块外观

| 参数 | 省略时的默认值 | 显式输入要求 |
| --- | --- | --- |
| `style.radius` | 0px（直角） | 非负整数；实际绘制不超过模块短边的一半，保留 JSON 原值 |
| `style.opacity` | 1（完全不透明） | `0～1` 的有限数值，允许小数；越界时报错 |
| `style.border` | 不绘制边框 | 启用时初始为 1px 黑色 `#000000` 实线，宽度和颜色支持 UI 调整 |

圆角超过模块短边的一半时，按该上限绘制，正常渲染，不将其视为非法参数。

边框包含在模块整体宽高中，内容区域先扣除两侧边框宽度，再扣除内边距。固定尺寸叶子的整体宽高不因启用边框而增大；自动尺寸容器根据子模块、间距、内边距和边框汇总自身尺寸。

边框 JSON 使用 `style.border: {"width": 1, "color": "#000000"}`，当前只有实线。省略 `border` 不绘制；`border: {}` 启用上述初始值。`width` 为非负安全整数，`0` 不绘制；`color` 沿用六位或八位十六进制。`null`、布尔开关和颜色字符串不作为边框对象的简写。

不透明度影响整个模块的绘制，不改变布局占位；`0` 表示全透明，仍保留模块尺寸和位置。UI 可用百分比展示和调整，文档中保存 `0～1` 的比例值。此参数不属于必须为整数的像素尺寸。

## 模块背景

背景属于每个模块自身的属性，通常在根模块上配置；子模块也可以单独设置背景。背景不另设为 `composition` 的独立画布属性，`composition` 仍控制最终输出尺寸。

模块未配置自身背景时默认透明、不绘制背景：子模块透出父模块背景，根模块未设置背景的区域保留 PNG 透明通道。背景支持用户通过 UI 修改并保存到文档；默认透明不回写为显式字段。

背景支持纯色和图片两种形式，纯色值沿用六位或八位十六进制格式。背景按模块完整区域绘制，包括内边距，不参与模块自然尺寸和内部内容布局的计算。

背景统一使用带 `type` 的对象，不接受颜色字符串简写：

```json
{"background": {"type": "color", "color": "#FFFFFF"}}
```

```json
{"background": {"type": "image", "assetPath": "images/bg.png", "fit": "cover", "align": "center", "verticalAlign": "center"}}
```

以上字段放在模块的 `style` 中。纯色背景必须有 `color`；图片背景的 `assetPath`、`fit`、`align`、`verticalAlign` 可省略，枚举与普通图片相同，但 `fit` 默认值不同。图片背景未选择素材时返回警告；省略整个背景则默认透明且不产生素材警告。

图片背景默认 `fit: "cover"`，水平、垂直居中，等比铺满模块区域，超出部分裁剪；与普通图片模块默认 `"contain"` 分开处理。图片背景的素材缺失或无法加载时沿用警告占位图规则，未配置背景本身则仍按默认透明处理。

## 最终输出尺寸

模块的自然布局尺寸和最终出图尺寸分开处理。最终 PNG 尺寸由 `composition.width` / `composition.height` 控制；根模块及其子模块仍按各自布局规则计算自然尺寸。

- 未指定最终输出宽高时，按自然布局尺寸出图。
- 顶层最终输出的 `width` / `height` 允许填写 `"auto"`，与省略对应字段等价。叶子模块仍必须指定具体宽高，不允许使用 `"auto"`。
- 允许只指定一个维度；只约束该方向，另一方向按最终布局自适应。
- 撤销此前渲染默认宽度为 `1200` 的方案，不用保底宽度覆盖内容自适应结果。
- 已指定输出尺寸时，优先调整间距以适应尺寸，保持子模块原始宽高。
- 普通输出自适应只调整根 `group` 的 `padding`、`gap`，内部嵌套 `group` 保持自身配置。极端情况下的统一缩小仍作用于所有模块及已确认的非文字参数。
- 横向、纵向分别计算实际间距，JSON 中仍可使用统一的 `padding` 和 `gap`。
- 空间充足时，`padding` 和 `gap` 按设定比例共同增大；默认比例为 `24:24`。
- 当 `padding`、`gap` 均为 `0` 且指定输出尺寸大于内容尺寸时，保持 `gap = 0`，额外空间平均分配到两侧 `padding`，使内容整体居中；不回写原始配置。
- 空间不足时，先减小间距；降至 `0` 仍放不下时，允许所有子模块使用同一个比例缩小，保持各自宽高比及模块间的相对大小。
- 自动缩小属于极端情况：继续生成图片，同时向用户显示警告，说明受影响模块、原布局尺寸、目标输出尺寸和实际缩放比例，并提示增大输出尺寸或减小子模块尺寸。
- 极端缩小时不缩放文字：文字字号及行高保持原值，按缩小后的可用内容区域和换行开关重新排版，超出部分直接裁剪；不因文字裁剪另发提示。
- 极端缩小时，内边距、边框宽度和圆角半径随模块按同一比例缩小，仅用于本次布局和绘制；原始 JSON 数值不变。计算后的像素值沿用最多一位小数的规则。
- 自动缩小属于可恢复的布局调整，与非法参数导致的渲染阻断分开处理。
