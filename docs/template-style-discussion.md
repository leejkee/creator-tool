# 模板与 Style 制作功能讨论

状态：需求讨论中，尚未开始功能实现。开发分支为 `feat/template-style-editor`，从讨论开始时的最新 `origin/main` 创建。

本文保存当前讨论，供后续会话继续确认。已提出的功能目标、建议方案和待确认选择分别记录；建议尚未获得确认，不作为新的需求基线。现行职责与规则仍以[架构](architecture.md)、[文档与文件](document.md)、[资源与复用](resources.md)为准。

## 已提出的功能目标

- 用户能够在应用中创建模板和 Style，并保存在本地。
- 项目随应用预载一部分模板和 Style。
- 用户能够通过应用内置编辑器编辑这些资源。
- 在独立的新分支开发，先讨论并确定功能细节。

## 当前基础与需要新增的能力

应用已有从完整图片 JSON 复制新文档的入口，以及底层 Style 一次性应用能力；尚未提供模板库、Style 管理界面和专用制作编辑流程。

现有模板定义与复制规则见[新建与模板复制](document.md#新建与模板复制)，模块资源协议和 Style 应用语义见[Style 与模块资源格式](resources.md#style-与模块资源格式)及[Style 一次性应用](resources.md#style-一次性应用)。本次将新增资源管理与编辑能力，其交付范围需要在确认后更新对应需求文档。

## 建议方案，待确认

### 模板与 Style 的定位

| 对象 | 保存内容 | 使用方式 |
| --- | --- | --- |
| 整份作品模板 | 完整画布、模块结构、示例图文、外观和素材 | 创建一份独立的新作品 |
| Style | 尺寸、间距、字体、颜色、背景、图片处理等参数，可包含子模块的参数配方 | 应用于已有模块，保留实际文字、图片内容、模块 ID 和结构 |

是否同时提供模块模板仍待确认：模块模板保存选中模块及其子模块，可插入已有作品；这与整份作品模板的创建用途不同。

### 制作与编辑流程

- 制作模板：从空白开始，或将当前作品“另存为模板”，复用现有画布和属性编辑器。
- 制作 Style：从选中模块提取参数，也可以新建；使用示例文字和图片预览效果，示例内容不保存到 Style。
- 资源管理：增加“模板”和“Style”入口，区分“内置”和“我的”，支持预览、编辑、复制、重命名和删除。
- 编辑内置资源：建议保存为用户副本；应用更新继续维护原始预置，用户修改独立保留。该编辑及更新策略尚未确认。
- 编辑保护：建议资源编辑沿用未保存提示、写入失败保留编辑、外部修改冲突保护。
- Style 使用结果成为作品的实际参数；保持现行的一次性应用语义，修改源 Style 后不联动已有作品。

### 本地资源库与素材

建议使用跨 workspace 共用的本地资源库，切换工作区后仍可使用同一批模板与 Style；是否改为每个 workspace 独立维护，尚未确认。

建议将模板和 Style 引用的图片复制到资源自身目录，使用资源时再复制到作品目录。由此使资源和作品各自拥有素材副本，删除模板或 Style 后不影响已经创建或应用的作品。

这项素材方案会扩展现行[保存与另存为](document.md#保存与另存为)中模板复制仅保持资源指向、不复制素材的规则，尚未获得确认，不能直接视为已经变更现行行为。

## 优先待确认的三个问题

1. **模板粒度**：首版只支持整份作品模板，还是同时支持“选中模块及其子模块保存为模板，再插入作品”？
2. **资源库位置**：模板和 Style 是跨 workspace 共用的本地资源库，还是每个 workspace 独立维护？当前建议全局共用。
3. **Style 覆盖方式**：沿用现行的受管理参数整体替换规则，还是增加局部 Style，例如只修改颜色和字体、保留原尺寸？现行规则下，配方遗漏的受管理参数也会清除；局部 Style 需要进一步确定参数选择与覆盖语义。

## 后续继续方式

先确认上述三个问题，再细化资源管理入口、内置资源编辑与更新策略、保存和素材独立性。将确认后的规则分别纳入架构、文档与文件、资源与复用需求，再开始实现；本文保留为讨论材料，不维护另一套正式参数或默认值清单。
