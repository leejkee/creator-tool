## 1. 目标与基本概念

为同类型工作保存可复用的默认模块，例如《王者万象棋》一图流攻略，
避免每次重新搭建结构、布局和样式。

| 概念 | 定义与关系 |
| --- | --- |
| Project（项目） | Agent 使用的工作目录，可含多张图片及 AGENTS.md；每图各有自己的 JSON 和 PNG，不设专用 pjt.json。GUI 只处理所打开的图片 JSON，不管理项目目录。 |
| Module（模块） | 一切描述图片内容的单元：文本框、图片、图文组合、其他模块的组合。任意模块均可单独导出 PNG。 |
| Style（样式） | 描述最小模块或组合模块如何渲染，可包含布局及各位置的子模块类型、样式；按布局、位置和类型匹配，不要求实际图文内容相同。 |
| Content（内容） | 模块中实际展示的文字、图片来源及子模块内容，与渲染样式区分。 |
| Template（模板） | 用于新建时复制参考的实际默认模块，保存结构、布局、各模块样式及背景等配置。已有模块的样式调整使用 Style。 |

从模板创建新模块时，复制模块数据，随后填充内容、调整布局或样式。
新模块与原模板独立，修改任意一方均不影响另一方；新模块的渲染不依赖原模板继续存在。
因此，模板是创建时复用的模块，不采用只保存模板引用和差异、渲染时再展开的方式。
图片、字体和脚本等外部资源的保存与解析规则另行明确。

继续采用便于 Agent 使用的项目目录工作方式。每张图片对应自己的创作 JSON，
其中内容字段和样式字段可分别修改；一个项目目录可保存多份这样的图片 JSON，不设项目汇总 JSON。
GUI 直接打开、编辑和保存指定 JSON，PNG 导出到该 JSON 所在目录；打开文件不以项目目录结构或 AGENTS.md 的存在为条件。
Style、Template JSON 集中存放在可配置的全局资源目录，由不同项目共用，实际路径由用户选择。
它们是可复用参数资源，不是第二份项目编辑状态，也不要求每个项目复制一套资源文件。
图片 JSON 可用 `style_1` 等标识表达待应用样式，应用与保存规则见 2.3。
应用后的实际参数保存于该图片 JSON，决定当前图片效果，例如字号已保存为 32，就按 32 渲染。

| 位置 | 保存内容 |
| --- | --- |
| 全局资源目录 | styles/、templates/、scripts/；路径由应用设置或 IMAGE_CREATE_TOOL_HOME 选择，默认位于用户配置目录的 resources/。 |
| 项目目录 | 每张图片各自的 JSON 和 PNG，以及自行维护的 `AGENTS.md`；素材和字体沿用可配置的资源路径。 |

项目说明 `AGENTS.md` 由使用者自行维护，应用不生成或覆盖。
Agent 创建和修改图片 JSON 时参考 [JSON 协议](../image_create_tool/resources/JSON_PROTOCOL.md)
和 [完整示例](../image_create_tool/resources/example.image.json)；Style/Template 应用、素材查询、预览与导出通过 GUI 完成。

## 2. 独立样式与批量应用

### 2.1 样式属性

通用视觉属性：

- 背景：纯色、图片、毛玻璃，以及透明度。
- 边框：是否显示、宽度、颜色。
- 对齐：垂直始终居中，水平可选左、中、右。

每个模块都可设置自己的底层毛玻璃背景：先绘制该模块背景，再覆盖内容；上方文字、图片等内容不参与模糊。

Style 可以包含布局描述，见第 3 节；不设置背景、边框等视觉装饰的模块仍可单独管理布局。

图片特有属性：

- 透明度：0–1。
- 非等比例填满目标区域。
- 按目标高度等比例缩放，宽度方向居中裁剪。
- 按目标宽度等比例缩放，高度方向居中裁剪。

文本框特有属性：

- 文字水平左、中、右对齐。
- 字号、字体；文字超过模块范围时按边界裁剪，具体规则见下文。

具体字段和示例以当前 JSON 协议为准。
组合模块的 Style 可同时描述自身背景等属性、布局，以及内部各位置子模块的样式。

### 2.2 独立设置与可选装饰

- 取消父子样式继承，最小模块和组合模块均独立应用自身样式，不设置跟随父级或向下传递的开关。
- 整张图片对应的组合模块可单独设置背景、边框等，不将这些属性复制给内部模块。
- 行模块及其他组合模块可不设置任何视觉样式，仅作为布局容器；只在需要的子模块中设置样式。
- 无样式的布局容器不额外绘制背景、边框等装饰，仍正常排列和渲染子模块。
- 文本、图片必需属性的缺省值由统一入口处理，不从父模块取得。

### 2.3 批量应用

- 多个最小模块或组合模块，可以批量应用匹配的 Style。
- 组合 Style 按布局、子模块位置和类型匹配，实际图片、文字可以不同，应用时保留各自内容。
  例如下面的 Style 只适用于第一行图片、第二行文字的两行一列模块；布局或对应位置类型不一致时不能直接应用。
- 模板用于新建模块时复制参考；批量修改已有模块使用匹配的 Style，不再将该操作称为批量套模板。
- 应用 Style 是一次性参数操作：从全局目录读取并解析样式，将实际参数写入目标图片 JSON。
  组合 Style 中的子样式引用也在此次应用中解析，不留下影响已有图片渲染的动态样式依赖。
- 应用时整体覆盖目标样式：新 Style 未提供的属性恢复统一默认值，不保留先前的本地样式调整。
  实际文字、素材来源和模块身份仍保留；组合模块按匹配位置替换对应样式。
- 后续直接编辑图片 JSON 中的内容和样式，允许逐步偏离最初的 Style/Template。
  修改图片不回写源 Style，也不修改其他已应用模块；修改全局 Style 不自动更新已有图片。
- 用户希望采用源 Style 的新参数时，再主动应用一次。正常重开、预览或导出不能重新套用源 Style 覆盖本地调整。
- 支持将当前模块的布局及各级样式参数“保存为新 Style”，供以后复用，不携带实际图文内容，不覆盖原样式。

```json
{
  "layout": [2, 1],
  "elements": [
    {"position": [0, 0], "type": "image", "style": "style_1"},
    {"position": [1, 0], "type": "text", "style": "style_2"}
  ]
}
```

这是全局组合 Style 的有效结构示例。`layout` 为 `[行数, 列数]`，`position` 为从 0 开始的 `[行, 列]`；
`style_1`、`style_2` 指向预先写好的图片和文字样式 JSON，应用时一并解析并写入目标图片，不包含实际图文内容。

### 2.4 文字超出模块范围

字号和模块大小由用户调整；不为溢出文字额外缩小字号或扩大已分配的模块区域。
渲染器必须将文字绘制限制在规定的模块边界内，超出部分裁剪，不能覆盖相邻模块。
项目中仍保留完整原文，预览和 PNG 导出采用相同的边界限制。
仅因字号过大或文本放不下而产生的裁剪不阻止导出；用户查看效果后自行调整。
这是对现有文字溢出阻断规则的明确调整，其他资源和布局错误另行校验。

## 3. 布局：以“行”为对齐单位

通常整体只有一列，各行按顺序排列；一行内部可以包含多列，也可以再次嵌套模块。
外层只需处理这一行所占区域，不必了解行内具体怎样排布。
布局描述包含宽 W、高 H、子模块排列及间距，不要求容器具有视觉 Style。

`(r, c)` 用来统一表达一行多列、一列多行，以及局部多行多列的组合。
它不要求整个文档建立统一列宽，也不要求不同行的列边界相互对齐。
例如某一行可放置一个内部为 2×2“田字形”的组合模块；外层仍将其作为一个模块参与排列。

尺寸交互按使用习惯确定：

- 调整外层模块尺寸，内部模块按布局适应可用空间。
- 默认同一行先扣除固定列宽和间距，其余自适应列均分剩余宽度。
- 同行统一行高，默认取行内最高模块的高度，较小内容垂直居中。
- 单独缩小内部图片时，若模块宽度已写死，模块宽度保持不变，图片在模块内部居中缩小。
- 若模块宽度未写死，模块宽度随图片一起缩小，呈现图片与模块同宽的效果。
  模块高度不随此次缩小一并收缩，而是保留上下空白，图片垂直居中。
- 应区分模块在布局中的占位与内部内容的显示大小，不能将两种调整混为同一操作。

固定列宽和间距超限时报告布局错误；局部网格空位保留位置，支持 gap/rowGap/columnGap。
不扩展为跨行统一列对齐，计算不引入父子尺寸的循环求解。

## 4. 内容、素材与图片预处理

- 文本内容：实际文字。
- 图片内容：图片来源，以及可选的 processor 或 processors 处理步骤，支持 script/function/params。
- 组合内容：实际子模块；模板复制后可独立调整结构和数量。
- 素材按文件名从指定素材目录搜索，沿用 `assetQuery`、别名与分类查询入口。
  新版检索入口随图片 JSON 协议确定，匹配歧义应明确报告。

图片处理脚本单独保存为文件，放在 `scripts/` 目录。
根据内容 JSON 找到处理函数，在图片进入后续渲染流程前完成裁剪等处理。
处理结果仅保留在内存，不覆盖本地原图，不持久保存中间图片。

当前采用渲染工作线程调用，全局资源目录 scripts/ 中的函数接收 RGBA 图片副本和命名参数，返回 Pillow 图片或 PNG 字节。
执行顺序为脚本处理、内置 crop、适配与绘制。源码和资源指纹改变时废弃旧结果；未实现预处理子进程。
预览与导出应使用相同的处理规则；处理失败或资源变化不能被当作成功结果导出。

## 5. 实施边界与顺序

继续使用 Python、PySide6、Pillow，保留 GUI、服务、渲染器的职责分工。
GUI 及服务围绕所打开的图片 JSON 工作，按文件管理编辑、监听、保存和外部变更，取消固定 `pjt.json` 入口和项目识别前提。
全局 Style/Template JSON 属于参数资源，项目 `AGENTS.md` 是 Agent 使用说明。
保留稳定 ID、内存撤销/重做、外部变更审阅、预览与 PNG 导出。
不擅自改变攻略内容，保留 `sourceNotes`。本次未新增或修改测试代码。

GUI 增加“打开终端”入口，在当前 JSON 所在目录启动用户指定的终端程序，Windows 默认使用 `pwsh`。
终端启动程序可配置；无需向上查找项目根目录，用户在该目录运行 Agent 或命令。

当前已具备嵌套容器、`column/row/fixed` 布局、基础样式、素材检索、裁剪与溢出诊断。
主要新增单项目多图片、全局参数资源、模板复制、独立样式与批量应用、行内组合布局、视觉效果和脚本入口。
实施时重点梳理 `itemRow.style` 中混合的布局/视觉字段，以及 `:text`、`:image` 子节点的编辑身份。

| 阶段 | 工作与交付 |
| --- | --- |
| 1. 规则与模型 | 定义独立图片 JSON 的协议、内容/样式字段及稳定 ID；落实样式一次性展开、整体覆盖及保存后独立的 Schema，核对现有 JSON 的数据兼容性，补齐示例与使用说明。GUI 不增加项目识别或迁移管理。 |
| 2. 模板与样式 | 实现全局资源加载、模板复制、Style 一次性整体应用和另存为新 Style；建立统一默认值入口，支持无装饰容器。GUI 与渲染器共用有效参数，区分保存数据与运行时计算结果。 |
| 3. 布局与绘制 | 落实默认均分宽度、同行统一行高及第 3 节缩图规则；先解析样式，再测量、排列和绘制。实现各模块的背景/毛玻璃、文字裁剪及其他视觉效果，支持模块单独导出。 |
| 4. 图片处理 | 确定脚本调用协议并接入内存结果；服务统一资源解析。将实际使用的样式、字体、素材、脚本与参数纳入资源身份，防止误用过期结果；原模板变化不影响已有实例。 |
| 5. 编辑工作流 | GUI 直接打开/保存 JSON，PNG 导出到同目录，支持模板新建、Style 批量应用及保存新样式。按文件监听和审阅；终端默认 pwsh、程序可配置，工作目录为当前 JSON 的目录。 |
| 6. 模板与验收 | 使用 `tool_test/` 复制资源制作万象棋模板，验证同项目多图片、跨项目共用参数、独立修改、批量样式、无样式容器及模块导出；形成正式 PNG 和验收记录。 |

验收至少覆盖：任意目录直接打开 JSON、PNG 同目录导出、一图一 JSON、共享全局资源、模板复制后独立、批量 Style、另存新 Style、组合样式匹配、无样式容器、
不同长度文本与不同比例图片、行内多列和田字组合、保存后重开、GUI 预览与正式导出一致。
修改全局 Style 后，已有图片及其 JSON 不变；重新应用后才更新，重开或导出保留本地调整。
重新应用时旧样式整体替换，缺失属性恢复默认，实际图文内容不变；默认多列均分且同行统一高度。
图片缩小时，分别验证固定宽度与自适应宽度，以及保留高度后的上下空白、垂直居中效果。
终端入口验证默认 pwsh、自定义程序，以及包含中文或空格的 JSON 路径，确认工作目录为该文件所在目录。
文字过大或过长时应裁剪在所属模块内，保留完整原文并允许导出，不影响邻近模块。
先检查 GUI 预览与问题提示，再导出 PNG；缺失素材、无效图片裁剪参数、字体加载错误等继续阻止正式导出。
旧项目图片仅作参考，不运行旧绘图脚本代替新应用验收。

## 6. 技术落地与验证范围

GUI 在界面中打开指定 JSON；默认同名 PNG 同目录导出。未设背景时透明；所选模块可单独导出，
未固定宽度时使用原画布宽度。图片按宽/高缩放后不足另一方向时居中留白。
Style/Template 使用可配置的全局目录，内置示例作默认资源，自定义同名文件优先。
单个文本可指定 style.font，字体、素材、脚本均参与资源身份校验；具体运行与配置见 [README](../README.md)。

当前验收流程为检查 GUI 预览与问题提示，再导出 PNG。此前的源码编译、GUI 离屏运行和服务工作流验证范围记于验收文档，其中原 CLI 命令仅作历史记录。
终端入口采用程序和参数数组启动，Windows 默认 pwsh；参数支持 {cwd} 占位，实际终端窗口尚需用户环境交互验收。
