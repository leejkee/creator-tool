# Python 应用服务模块

状态：第一版已实现于 `image_create_tool/service.py`，结构、操作与存储分别在 `model.py`、`assets.py`、`storage.py`。总体约束见 [dev.md](dev.md)。本文件定义文档模型、文件监听及 GUI—服务交互；渲染协议见 [PYTHON_RENDERER.md](PYTHON_RENDERER.md)。

## 1. 职责与解耦

服务线程管理项目、文档、文件监听、保存、内存历史和任务调度。应用内部只有服务线程写项目 JSON；Agent 或用户也可以直接编辑同一个文件，其修改通过监听进入审核流程。服务是单进程内的 Python 模块，不是 HTTP 服务或独立服务进程。

服务不依赖 PySide6/Pillow，不计算文字位置。GUI 依赖 `ApplicationService` 端口；服务依赖 `RenderExecutor` 端口；启动入口组装 Qt 桥接和线程执行器。线程间传递只读结果与独立文档快照，不共享可被多个线程修改的 dict。

一个常驻服务线程串行处理 GUI 命令、文件轮询与渲染结果。轮询在同一个线程事件循环中按时执行，不能用无限阻塞的文件监听循环阻止命令处理。渲染结果投递回服务队列后再更新状态；GUI 不在主线程等待文件 I/O。

## 2. 文档模型（唯一协议定义）

### 工作目录与项目配置

打开的是工作目录，服务先检查根目录的 `pjt.json`。首版识别规则是：文件可解析为 JSON 对象，且包含字符串字段 `image-create-tool-version`，应用当前写入值为 `"v0.0.1"`。这个字段用于识别本应用项目；暂不设计版本迁移机制，不要求只有当前版本值才能识别。

没有 `pjt.json` 或没有该标记字段时，按空项目打开。已有文件无法解析时显示读取问题并保留原文件；不能因视为空项目自动覆写已有文件。空项目先使用内存默认配置，在用户明确初始化/保存项目时写入标记及配置。

最小配置：

```json
{
  "image-create-tool-version": "v0.0.1",
  "assetsDir": "assets/",
  "outputsDir": "outputs/"
}
```

- `assetsDir` 是素材根目录，可指向工作目录之外的位置；默认工作目录下的 `assets/`。
- `outputsDir` 是默认输出目录，同样可以自定义；默认工作目录下的 `outputs/`。
- 相对路径一律相对于打开的工作目录，不相对于应用启动目录。绝对路径允许指向外部目录，原路径字符串保存在配置中，服务解析为实际路径。
- 字段省略时使用上述默认值，显式空值或错误类型提示用户修正。不存在的素材目录提示暂无资源，不阻止空项目打开；输出目录在首次导出时按需创建，失败则报告。
- 配置和内容仍保存在同一个 `pjt.json`。只含上述最小配置也属于有效空内容项目；`modules` 等内容字段在开始创作后补充。
- 首版只做配置读写，不增加数据库、单独索引文件、迁移或目录扫描发现项目的规则。监听的是工作目录根部的 `pjt.json`。

### 可编辑内容

一个 `pjt.json` 同时保存模块与合成规则。持久化内容包含用户文字、素材引用和排版规则；实际坐标、换行与模块高度属于渲染结果，不能作为第二份独立文档维护。

```json
{
  "image-create-tool-version": "v0.0.1",
  "assetsDir": "assets/",
  "outputsDir": "outputs/",
  "documentId": "guide_001",
  "revision": 1,
  "title": "装备攻略",
  "sourceNotes": "无尽之刃：提高暴击伤害。",
  "modules": [
    {
      "id": "module_equipment",
      "title": "装备说明",
      "layout": { "type": "column", "padding": 24, "gap": 16 },
      "elements": [
        {
          "id": "equipment_001",
          "type": "itemRow",
          "image": { "assetQuery": { "name": "无尽之刃", "category": "equipment" } },
          "text": "无尽之刃：提高暴击伤害。",
          "style": { "fontSize": 24, "color": "#FFFFFF" }
        }
      ]
    }
  ],
  "composition": {
    "width": 1200,
    "height": "auto",
    "background": "#151923",
    "padding": 32,
    "gap": 24,
    "moduleOrder": ["module_equipment"]
  }
}
```

- `image-create-tool-version` 用于项目识别；`revision` 用于应用会话中的内容状态，两者不混用。服务为接受的状态分配递增版本，外部编辑不需要主动增加它。内容指纹与会话标识用于区分文件变更，不能仅凭外部 `revision` 判断是否变更。
- 模块与元素使用稳定 ID，复制生成新 ID，重排不变；组合组件子元素也有可寻址 ID，组件展开及覆盖值的具体 Schema 后续补全。
- 首版支持 `text/image/rect/group`、标题块和 `itemRow`；自动布局保存参数及位置偏移，固定布局保存显式边界。所有文档坐标使用逻辑像素。
- 图片显示框与原图裁剪分别保存，默认 `contain`；裁剪必须在原图边界内，不静默截断。
- 高度可自动计算或固定；固定画布溢出由渲染器报告，正式导出阻止。
- `sourceNotes` 只保存最初笔记，不反向覆盖编辑内容。
- 文档记录模板 ID/版本；项目配置固定字体及模板，修改既有模板不得静默改变已保存文档。有效样式由指定模板和文档覆盖值产生。

正式 Schema 尚待逐项细化；GUI 和渲染器都通过此协议工作，不定义各自的文档格式。

## 3. 素材管理

索引记录 `assetId`、名称、别名、类别、相对于配置素材目录的路径、媒体类型、尺寸及文件哈希。服务读取 `assetsDir`，允许它位于工作目录之外。首版索引在内存中建立；必要元数据放进唯一项目 JSON，不单独创建 `assets-index.json` 或 `project.json`。

`assetId` 优先，否则按类别及名称/登记别名精确匹配。唯一匹配写入引用；零匹配返回 `ASSET_NOT_FOUND`，多个匹配返回 `ASSET_AMBIGUOUS` 与候选。近似匹配只推荐候选，不自动选择。

缺素材草稿允许保存与占位预览，正式导出阻止。GUI 导入素材后复制到配置的 `assetsDir`，该目录可位于工作目录之外。渲染任务使用服务解析后的资源清单，渲染器不再次猜测素材。

## 4. GUI—服务交互协议（唯一协议定义）

命令方法返回 `Future[CommandResult]`，读取也通过同一端口获得快照。参数和返回值为普通数据类型；具体命名可在实现阶段调整，但语义不能由模块各自改变。

| 方法 | 输入 | 成功输出 |
| --- | --- | --- |
| `open_project` | 工作目录 | 项目识别状态、有效配置、内容及问题列表 |
| `set_project_config` | 当前版本、资源/输出目录配置 | 已保存配置或写入错误 |
| `get_document` | 文档 ID | 文档副本、当前版本 |
| `apply_operations` | 文档 ID、基础版本、操作列表 | 新版本、文档副本、操作摘要 |
| `undo / redo` | 文档 ID、基础版本 | 新版本、文档副本 |
| `search_assets` | 名称、类别 | 候选素材及缩略图信息 |
| `import_asset` | 用户选定的外部路径 | 新素材元数据 |
| `request_preview` | 文档 ID、版本、目标/候选 ID（如有） | 任务 ID、状态 |
| `get_preview` | 渲染 ID | PNG 字节、布局、版本或缓存失效错误 |
| `request_export` | 文档 ID、版本、输出路径 | 任务 ID、状态 |
| `get_job` | 任务 ID | 任务状态、问题、产物信息 |
| `get_external_change` | 候选 ID | 基线、当前内容、外部候选及字段差异 |
| `preview_external_change` | 候选 ID、预览目标 | 外部候选或合并结果的预览任务 |
| `resolve_external_change` | 候选 ID、当前版本、最新文件指纹、选择及冲突取值 | 已接受并写回的文档，或候选已失效错误 |
| `close_project / shutdown` | 项目标识或关闭请求 | 保存与任务清理结果 |

统一结果包含 `requestId`、`ok`、`data`、`issues`；失败额外包含 `error`。问题包含 `code/message/severity/documentId/moduleId/elementId/field`（适用字段），冲突包含当前版本。异常转成结构化错误，不让 GUI 解析报错文本猜原因。

操作按明确类型提交，如 `set_text`、`set_style`、`replace_asset`、`set_crop`、`move_element`、`resize_element`、`add/delete/duplicate_element`、`reorder_modules` 和 `set_composition`；一组操作全成功或全失败。操作负载只能包含对应类型允许的字段，不能用任意路径修改服务内部状态。

```json
{
  "documentId": "guide_001",
  "baseRevision": 1,
  "operations": [
    { "type": "set_text", "elementId": "equipment_001", "text": "无尽之刃：提高暴击伤害。优先合成。" }
  ]
}
```

以上文案修改示例表示用户明确输入的编辑，不授权 Agent 自行添加建议。

订阅入口为 `subscribe(callback) -> unsubscribe`。事件信封包含 `eventId`、递增 `sequence`、`type`、`documentId`、`revision`、`requestId`（如有）、`payload`。

| 事件 | 含义 |
| --- | --- |
| `document_changed` | 新内存版本、操作摘要与 `saveState` |
| `job_changed` | 任务状态变化，含任务 ID 与目标版本 |
| `preview_ready` | 渲染 ID、版本、问题；GUI 通过 `get_preview` 取图像及布局 |
| `export_ready` | 导出任务 ID、版本、文件路径和尺寸 |
| `assets_changed` | 素材索引已更新 |
| `external_change_pending` | 外部候选 ID、文件指纹、差异和待处理状态 |
| `external_change_invalid` | 外部文件无法读取/解析/校验，当前内容仍保留 |
| `external_change_resolved` | 用户选择及接受后的版本 |
| `service_error` | 后台异常及恢复状态 |

事件按服务序列发布，`document_changed` 包含 `saveState`，区分已写回和等待外部审阅的内存修改；只有写入成功才能标为已保存。产物入缓存后才能发布 `preview_ready`。订阅初期先读取当前快照，事件遗漏时重新读取；事件不充当持久化历史。回调从服务线程触发，经 GUI 桥接进入主线程，不持锁调用外部回调。

## 5. 版本、保存与历史

`baseRevision` 不一致时拒绝提交，不自动重放。首版以 GUI 编辑为主，正常操作按交替发生设计；服务写回时短暂获得系统级文件写入保护。每次保存取得保护后再核对内容指纹；已有外部变化则进入候选流程，本次 GUI 修改保留在内存，不直接覆盖。保存成功才标为已保存；失败保留内存输入并明确报错。

首版撤销/重做历史只在内存中保存，关闭应用后清空。撤销产生新的递增版本，批量操作为一个事务；预览不进入历史。“恢复”默认恢复外部修改前当前编辑状态，不代表历史版本回退。

```text
workdir/
  pjt.json                  # 唯一长期保存的项目 JSON
  assets/                   # 默认素材目录，配置可指向外部位置
  cache/                         # 图片等可重建缓存，不保存 JSON 快照
  outputs/                  # 默认输出目录，配置可自定义
```

项目配置、模块、合成规则及需要持久化的资源元数据保存在一个 JSON 中；基线、当前状态、外部候选、合并预览及撤销历史都是内存快照，不产生第二份草稿或版本 JSON。

目录设置修改同样经过服务写回；外部修改配置时也走候选审阅。接受 `assetsDir` 修改后重建内存索引并失效旧资源预览，接受 `outputsDir` 修改后使用新的默认导出位置。渲染请求使用已解析路径，不让渲染线程猜测路径基准。

### 服务保存时的文件保护（Windows 首版）

使用 Windows 文件句柄的共享模式保护实际 `pjt.json`，不是仅使用 `threading.Lock` 或创建一个其他工具可能忽略的 `.lock` 文件。以读写权限打开文件，仅允许 `FILE_SHARE_READ`，不允许 `FILE_SHARE_WRITE/FILE_SHARE_DELETE`；成功打开后，其他普通文件操作无法取得写入、删除或重命名权限，直到该句柄关闭。锁只覆盖保存阶段，不覆盖用户查看、渲染或日常文件监听。

保存顺序：

1. 在内存校验并序列化待保存 JSON，准备完整字节。
2. 取得上述受保护句柄，打开时不先截断文件；如果外部已持有不兼容句柄，本次获取会失败，不能假设 GUI 可以抢占它。
3. 用该句柄读取现有内容并核对预期指纹；不一致时释放句柄，读入外部候选，等待用户合并/恢复。
4. 指纹符合时，用同一句柄从开头写入全部字节、设置正确文件长度并刷新。不能另开一个写入句柄绕过自己持有的共享限制。
5. 更新自身写入指纹与保存状态，在 `finally` 中关闭句柄释放保护；通知 GUI 并请求预览。

文件占用返回 `FILE_BUSY`，保留未保存修改，可短暂有限重试或由用户重试；不阻塞 GUI、不无限等待。外部进程在保护期间尝试写入会失败，也需要稍后重试。首次初始化不存在的 `pjt.json` 时同样使用非截断创建和共享限制，若发现意外已有内容则报告而不覆写。

由于禁止删除共享会阻止替换文件，本方案对 `pjt.json` 使用受保护句柄原地写入，不再同时使用临时文件原子替换。进程或系统在写入途中中断仍可能留下不完整文件，这是首版选择短暂排他写入与单份数据的取舍；常规写入失败保留内存状态并提示，不能报告成功。PNG 导出仍可使用临时文件替换，不受该规则影响。

此保护适用于 Windows 普通文件访问，不宣称跨平台、内存映射等所有访问方式都能被同样阻止。实现依据见 [Windows CreateFileW 共享模式](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。同一项目只允许一个 GUI 实例，平时仍允许 Agent 编辑。

## 6. 文件监听、预览与合并

服务线程定期检查同一个 `pjt.json`，结合路径存在性、文件元数据与内容指纹检测改动；定期核对内容，避免仅凭时间戳漏掉变化。收到变化后短暂去抖，再读取完整内容并解析/校验；半写入、非法 JSON 或文件暂时不存在时报告问题并重试，不清空当前文档，也不自动覆盖外部文件。

记录应用自身写入的内容指纹，识别自身保存产生的通知；不能用简单时间窗口忽略全部文件变化。外部原子替换后仍检查同一路径，文件改名或删除必须有明确状态。

内存保留三份必要状态：`B` 为外部修改前最后同步的基线，`L` 为当前编辑状态，`E` 为新读到的外部候选。GUI 尚未提交的表单值仍保留；审阅前可提交为内存编辑并纳入 `L`。发现 `E` 后暂停自动写回，用户继续编辑只更新 `L` 和内存版本，避免立即覆盖文件中的候选。

候选有独立 `candidateId` 与内容指纹。外部再次修改时替换候选并通知 GUI；旧候选的接受命令或渲染结果不能应用。候选预览带独立标识，不改变当前编辑状态；用户可切换当前图、外部候选图和待合并图。

用户选择：

- **合并**：按稳定模块/元素 ID 与字段比较 `B/L/E`。只有外部改变的字段取 `E`，只有本地改变的字段取 `L`，双方改成相同值可直接保留。双方改成不同值、删除与修改冲突、重复新增 ID、模块顺序冲突都列出供用户选择，不用 LLM 猜测。数组重排按显式顺序规则处理，不能按序号对齐元素。
- **恢复当前内容**：拒绝外部候选，把当前 `L` 写回同一个 JSON。不会撤销用户已有微调，也不恢复到更早的 `B`。
- **暂不处理**：候选留在内存，暂停写回，允许比较及内存编辑。关闭时须处理或明确选择放弃未落盘本地修改；如果放弃，磁盘保留外部内容。

确认前核对当前版本，并在取得保存保护的句柄后核对磁盘指纹；有新变化则返回 `EXTERNAL_CHANGE_STALE` 并重读候选。确定结果经校验、受保护写回成功后成为新的基线和当前状态。外部 `documentId` 改变属于身份冲突，首版不自动合并为当前文档。

文件监听负责发现外部变化，系统共享限制负责保护服务保存阶段；两者职责分开。暂不设计 Agent 与 GUI 持续同时写入的复杂协调，Agent 完成一次修改后等待用户处理。保护不会把已经发生的外部修改自动判为可丢弃，也不会在整个应用运行期间阻止 Agent 写入。

应用未接受的候选仅在内存，关闭或崩溃后无法从唯一 JSON 恢复之前的 `L/B`；这是不保存版本副本的明确限制。

## 7. 服务—渲染线程协作

通过 `RenderExecutor` 向一个常驻渲染线程提交请求。服务取独立快照，解析资源并固定指纹；输入不包含可变当前文档或 Qt 控件。当前预览与外部候选预览使用不同目标标识，候选的旧图不能替换当前图。

任务状态为 `queued/running/succeeded/failed`，被合并的预览标记 `superseded`。每个预览目标的待执行请求只保留最新状态，在线程空闲时提交，队列有界。

渲染线程完成后只投递结果到服务队列；服务校验版本/候选 ID 后通知 GUI。正式导出不合并、固定内容，后续编辑不影响它。GUI 主线程响应导出按钮和选择路径；耗时渲染在线程中进行，最终 PNG 写入在服务线程进行。存在未决外部变化时先处理合并/恢复，再导出，避免不清楚地导出候选或旧内容。

正式导出由服务复核阻断问题、尺寸和资源指纹；同版本、完整分辨率、校验通过的缓存可以复用。PNG 先写临时文件再替换目标，成功后才发导出事件。缓存失效返回 `ARTIFACT_EXPIRED` 并允许重新生成，不用其他版本图片代替。

资源文件不能在任务中途悄悄更换，发现变化则失效缓存并报告。同进程内传递不可变 PNG 字节与只读布局，不再使用跨进程共享内存。工作线程不能更新控件，Qt 桥接在 GUI 主线程消费结果。

```text
guide-editor assets search --project <project_dir> --name <name> --category <category>
guide-editor validate --project <workdir>
guide-editor open --project <workdir>
```

Agent 直接创建或修改工作目录根部的 `pjt.json`。首次通过 CLI 打开目录；应用运行后，Agent 修改同一文件，由服务线程发现并送入候选审阅流程，不要求 Agent 写通信脚本或发送消息。GUI 同样通过“打开工作目录”进入项目。

命令入口属于同一桌面程序，打开后进入主线程 GUI 事件循环，不创建 GUI 子进程和确认管道。Agent 环境可将应用作为独立桌面程序启动后结束调用；运行中的桌面应用内部仍只有一个进程。再次打开已占用项目报告信息，不启动第二个可写实例。

## 9. 独立验收

- 用假的渲染执行器和唯一 JSON 验证打开、匹配、版本冲突、保存失败与内存撤销，不需要 GUI。
- 排队有界，过期预览不覆盖当前状态，正式导出固定版本且成功事件对应已落盘文件。
- 缺失/歧义素材不被猜测替换；渲染失败后文档仍可保存。
- 外部合法、半写入、重复变更、应用自身保存、文件替换与删除均有正确状态；审阅中自动保存不覆盖候选。
- 合并保留不冲突修改，冲突由用户选择；恢复写回当前内容；外部候选及内存历史不产生额外 JSON。
- 同项目第二个可写实例被拒绝；重启后撤销历史清空。
- 服务持有保护句柄期间，外部普通写入/删除/替换被拒绝，释放后可再次编辑；外部先占用时服务报 `FILE_BUSY` 并保留 GUI 修改。加锁后指纹变化转入候选，不先截断文件。
- 根目录无 `pjt.json` 或无标记时显示空项目；最小配置能识别，默认路径、外部绝对路径及相对路径基准正确；不自动覆盖已有无标记文件。
