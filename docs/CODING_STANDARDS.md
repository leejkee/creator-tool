# 旧 Python 代码规范（待废弃）

> **待废弃：仅供迁移核对旧 Python 实现。** 本文不作为当前 Tauri 分支的架构、实施计划或验收依据，也不约束 Rust / TypeScript 实现。后续开发以 [开发说明](dev.md) 和 [README 的迁移范围](../README.md#tauri-迁移任务与本分支范围) 为入口。

适用范围：`image_create_tool/`、`tests/` 及项目维护脚本。运行环境以
`pyproject.toml` 的 Python 3.11+ 为基线，使用工作区 `.venv/Scripts/python.exe`。

下文的实现约束与工具建议仅适用于旧 Python 工程，不作为新架构的编码规范。图片 JSON 的旧协议可用于迁移核对，见 [JSON_PROTOCOL.md](../image_create_tool/resources/JSON_PROTOCOL.md)。

## 1. 基本原则

- 可读性、正确性、可验证性优先；使用能表达当前需求的最简单结构。
- 同一规则只有一个权威定义，调用方通过接口复用，避免复制默认值和校验逻辑。
- 输入边界负责解析与校验，核心计算消费已明确的数据，输出边界负责序列化和保存。
- 将纯计算与文件、线程、GUI 等副作用分开，保持现有 GUI、服务、渲染职责。
- 为明确的变化需求建立抽象；不要提前引入通用插件系统、基础类体系或依赖注入框架。
- 重构默认保持文档内容、稳定 ID、原有行为和文件兼容性。行为变化必须明确说明并验证。

## 2. 字面量、常量、配置与资源

### 2.1 按含义决定存放位置

不禁止所有字面量。需要消除的是含义不明的数值、分散的业务规则和难以维护的重复定义。

| 数据性质 | 存放位置 | 本项目示例 |
| --- | --- | --- |
| 算法中的明显数值或空值 | 使用处 | `0`、`1`、`None`、空集合、两侧边距公式中的 `2` |
| 工程限制、稳定约定 | 所属模块的命名常量 | 最大画布像素数、项目文件名、协议版本 |
| 有限状态或模式 | `Literal` 或 `Enum` 定义 | 布局方向、渲染目标、任务状态 |
| 用户的内容与布局决策 | 当前图片 JSON | 文字、素材引用、尺寸、间距、内容裁剪、模块独立样式 |
| 可复用的布局与视觉参数 | 全局 Style/Template JSON | 字体、颜色、圆角、边框、组合布局及默认模块 |
| 应用运行参数 | 构造参数或专用配置类型 | 文件轮询间隔、任务等待时间；仅有实际需求时开放配置 |
| 特定机器的资源位置 | 资源解析与平台适配边界 | 字体路径、工作目录、素材目录 |
| GUI 标签及短提示 | 所属界面模块 | “导出 PNG”；需要复用或国际化时再提取 |
| 可供程序判断的错误码 | 错误契约所属模块 | `TEXT_OVERFLOW`、`RESOURCE_CHANGED` |

同一个数值可能有不同含义：项目布局中的 `24` 是用户数据，主题中的 `24` 可能是字号，
算法中的 `24` 若表示限制则需要命名。不要因为数值相同就合并成同一常量。

### 2.2 常量的写法与归属

模块级常量使用 `UPPER_SNAKE_CASE`；涉及单位时在名称中体现单位。
需要静态检查重赋值时使用 `Final`，但它不提供运行时不可变保证。

```python
from typing import Final

MAX_CANVAS_PIXELS: Final[int] = 100_000_000
DEFAULT_POLL_INTERVAL_SECONDS: Final[float] = 0.3
```

- 常量放在拥有该规则的模块，由其他模块导入。确有跨模块共享契约时，才建立小型契约模块。
- 不建立收纳所有数值、字符串、颜色和路径的全局 `constants.py`。
- 名称表达用途，例如 `MAX_CANVAS_PIXELS`；不要使用 `VALUE_100M`、`DEFAULT_NUMBER`。
- 常量声明处允许出现字面量。不要为 `0`、`1`、`"utf-8"` 等明确值增加无意义间接层。
- 模块级共享数据优先使用 `tuple`、`frozenset`。默认字典每次创建新实例，禁止共享可变默认参数。

### 2.3 默认值只解析一次

当前字体、颜色和组件尺寸等默认值散落在 GUI 与渲染器中，后续重构应逐步收敛。

- 文档默认值由模型规范化入口提供，视觉默认值由统一样式入口提供。
- GUI 展示解析后的有效值，渲染器使用同一份有效样式，不分别猜测默认值。
- GUI 手动修改一个属性，只提交该属性。应用 Style 是一次性整体覆盖，未提供属性恢复默认；展开参数保存至图片 JSON，不采用继承或动态联动。
- 缺失字段与显式值要区别处理。`0`、`False`、空字符串若合法，不得用 `value or default` 覆盖。
- 不用默认值掩盖非法输入。未知模式、无效颜色和不支持的视觉效果应报告明确问题。
- 文本默认样式与容器无装饰默认值应明确，不能在 GUI 和渲染器中分别定义相互矛盾的默认值。

### 2.4 字符串和协议字段

JSON 字段名可以直接出现在序列化和解析代码中；不要求把每个 `"width"` 都改成常量。
跨模块传递的请求、结果和状态应优先建立类型契约，减少手写字符串和无结构字典。

有限集合优先选择一种表达方式：只需要约束字符串时使用 `Literal`；需要运行时成员身份或行为时使用 `Enum`。
引入枚举不能隐式改变既有 JSON 字符串，序列化边界必须明确转换。

## 3. 命名、格式与注释

- 参考 PEP 8：四空格缩进；函数、变量、模块使用 `snake_case`，类使用 `PascalCase`。
- 新增代码采用 100 字符目标行宽，这是本项目约定；长 URL 等不为凑行宽牺牲可读性。
- 一行一个语句，避免分号串联赋值、信号绑定或控件操作。
- 导入分为标准库、第三方库、项目内模块；禁止通配符导入，避免导入时执行文件读写或启动线程。
- 布尔变量表达判断，例如 `is_exportable`；有单位的变量写明单位，例如 `timeout_seconds`。
- 使用具体名称；除局部坐标等明确场景外，避免 `data`、`obj`、`tmp` 等模糊名称。
- 公共接口和复杂算法写 docstring，说明输入、输出、约束与副作用；注释解释原因及兼容取舍。
- 注释和 docstring 可以使用中文。不要逐句复述代码；TODO 应说明未完成的具体事项。

格式由统一工具执行。不要同时维护多个职责重叠的格式化器。

## 4. 类型与数据契约

- 新增公共函数、跨模块接口、队列消息和返回结果必须标注参数与返回类型，含 `-> None`。
- 使用 Python 3.11 支持的写法：`list[str]`、`Path | None`；不使用要求更高 Python 版本的语法。
- JSON 字典契约优先用 `TypedDict`；解析后的内部值对象可用 `dataclass`。
- `Literal` 表达有限取值，`Protocol` 只用于确有多个实现或测试替身的接口。
- `Any` 主要留在外部输入解析处，校验后收敛为具体类型。不要沿渲染流水线传播无结构的 `dict[str, Any]`。
- 类型注解、`TypedDict` 和 `cast()` 不执行运行时校验。JSON、文件内容和 GUI 输入仍必须校验。
- `frozen=True` 的 dataclass 仅阻止字段重新赋值；内部含列表或字典时仍可变，不能据此宣称快照不可变。
- 不为减少几行校验代码立即引入新的模型框架。若引入依赖，说明它解决的具体问题及迁移成本。

优先为 `RenderRequest`、`RenderResult`、问题列表和有效样式补齐类型；不要求一次性改写整个文档模型。

## 5. 模块与副作用边界

| 部分 | 责任 | 边界 |
| --- | --- | --- |
| 模型与契约 | 数据类型、校验、文档操作、合并 | 不导入 Qt 或 Pillow，不直接操作 GUI |
| 样式解析 | 本地资源解析、结构匹配、一次性参数替换 | 返回新文档，不直接保存；由服务完成受保护写入 |
| 布局计算 | 约束、测量、最终边界 | 测量可使用字体接口，不读写当前编辑状态 |
| 渲染器 | 消费独立快照、绘制、返回图片与问题 | 不更新控件，不保存正式项目或 PNG |
| 服务 | 状态、历史、文件监听、资源快照、调度、保存 | 不依赖 Qt，串行管理当前文档 |
| GUI | 显示和收集操作 | 不直接写图片 JSON，不自行重算布局或有效样式，不依赖项目目录 |

函数尽量完成一个可描述的任务。解析、测量、布局、绘制和保存出现独立职责时拆分；
不以任意行数上限或“所有函数都必须拆小”为目标。

依赖可以通过普通参数或构造参数传入，例如渲染函数、时钟和资源解析器，方便独立验证。
不要为了注入一个函数建立复杂容器。

## 6. 校验、异常与诊断

- 外部输入先验证类型、范围和结构，再进入计算。数值检查包含非有限值，并在需要时排除 `bool`。
- 明确区分缺失字段、非法字段和不支持的功能；新旧文档通过明确版本或兼容入口处理。
- 解析阶段发现错误尽早返回；内容溢出等依赖测量的问题在对应阶段报告。
- 可预期业务失败使用结构化问题或领域异常，携带稳定错误码及可定位字段。
- 错误码供程序判断，提示文字供用户阅读；测试不依赖整句中文提示。
- 只在能够处理的地方捕获异常。禁止 `except: pass`，禁止用空结果冒充成功。
- 顶层命令和线程任务边界可捕获 `Exception`，但必须报告失败并保留 traceback 日志；不要吞掉退出信号。
- 转换异常使用 `raise ... from exc` 保留因果关系。错误应包含节点 ID、字段路径或资源身份。
- `assert` 用于内部不变量及测试，不用于校验用户 JSON。
- 日志使用 `logging.getLogger(__name__)`；GUI 的问题提示与诊断日志分别处理。
- 不记录整份攻略、素材文件内容或大量图片字节；日志聚焦任务身份、阶段、资源指纹和错误上下文。

## 7. 文件、线程与可复现性

- 文件路径使用 `pathlib.Path`；文本文件显式指定 UTF-8；资源用上下文管理器释放。
- 相对路径的解析基准必须明确。用户资源以工作目录为基准，包内资源不能依赖启动时的当前目录。
- 不在核心计算中硬编码开发机绝对路径。平台字体查找集中在资源适配层，不能静默替换用户指定字体。
- 每张图片保存唯一描述 JSON，保留受保护保存流程；不得为通用“原子写入规范”擅自改变文件锁与外部审阅协议。
- 服务独占当前文档的修改权；渲染任务只消费自己的快照，结果发布后不再修改。
- Qt 控件只在主线程访问。工作线程通过既有队列与 Qt 桥接返回结果。
- 异步结果通过任务身份、项目会话、内容和资源身份检查过期，不能仅比较文档 revision。
- 资源指纹覆盖素材、实际字体、脚本与参数；已应用的 Style 参数属于图片内容身份，源 Style 后续修改不影响已有图片。版本标签不能替代实际内容指纹。
- 新增缓存前先明确所有影响结果的输入和失效规则；不以缓存弥补不确定的状态读取。
- 不使用长时间 `sleep` 协调线程；优先使用事件、队列和带超时的等待。时间差使用单调时钟。

## 8. 测试与变更验收

- 未经用户明确要求不新增或修改测试代码。用户授权后使用 pytest，检查可观察行为、约束边界和真实故障，不复述内部实现。
- 布局和资源逻辑发生变化时，覆盖正常、非法及边界输入，例如混合尺寸、嵌套容器、缺失资源和文字溢出。
- Style 验收覆盖默认值、布局/位置/类型匹配、整体覆盖、源文件独立、参数快照及资源变化后的过期结果处理。
- 文件测试使用临时目录；真实业务验收使用 `tool_test/` 的复制资源，不运行旧渲染脚本替代应用验收。
- 字体相关测试使用明确资源；普通回归优先比较换行、边界和错误码。像素快照需要固定字体与相关运行环境。
- 时间相关逻辑优先注入时钟或等待条件，避免依赖固定休眠猜测线程完成时间。
- 文档、注释等低影响改动无需机械添加测试；行为变更运行对应检查，通过后不无理由重复扩大测试。
- 修改内容或渲染行为时先检查 GUI 预览与问题提示，再导出；缺资源、非法裁剪、字体或脚本错误、布局越界阻断导出，文字裁剪仅为警告。

## 9. 推荐工具与渐进接入

目前 `pyproject.toml` 只声明了 pytest 测试依赖，尚未接入下列 Ruff 和 mypy 检查。
工具接入应单独提交，固定可复用的工具版本，并处理或明确隔离历史问题，不在功能重构中混入全库格式化。

| 用途 | 选择 | 初始范围 |
| --- | --- | --- |
| 格式化、导入排序与静态规则 | Ruff formatter + linter | 统一行宽 100、目标 `py311`；建议先启用 `E4`、`E7`、`E9`、`F`、`I` |
| 类型检查 | mypy | 先检查新增契约和纯计算模块，再逐步扩展到服务与 GUI |
| 行为验证 | pytest | 保留现有体系，按改动补充有价值的用例 |
| 工具配置 | `pyproject.toml` | 统一配置入口，避免重复配置文件 |

后续再按收益启用 Ruff 的 `UP`、`B`、`SIM` 等规则，不直接启用全部规则。
类型检查范围应明确记录；不要求旧工程立即全量 strict，也不能用全局忽略隐藏新增问题。
如需抑制规则，限定到具体规则或错误码，并说明原因。

工具接入后使用的命令示例（本次文档变更未安装或执行这些工具）：

```powershell
.venv/Scripts/python.exe -m ruff format --check image_create_tool tests
.venv/Scripts/python.exe -m ruff check image_create_tool tests
.venv/Scripts/python.exe -m mypy <已接入类型检查的模块路径>
.venv/Scripts/python.exe -m pytest
```

新增依赖需要实际收益，区分运行依赖与开发依赖。保留现有 setuptools 构建方式，
不为采用代码规范同步切换包管理器或目录结构。

## 10. 本次重构的优先应用点

1. 为渲染请求、结果和问题列表建立明确契约，保留既有 JSON 字段和稳定 ID。
2. 将视觉默认值统一到样式解析层，GUI 与渲染器共同使用有效样式。
3. 将 `itemRow.style` 中的布局字段逐项分类，先明确兼容规则，再迁移。
4. 集中维护画布限制、任务状态和错误码；不把所有字面量搬进常量文件。
5. 服务统一通过资源解析入口建立渲染快照，保持 Style 一次性应用和字体、素材、脚本身份一致。
6. 按独立变更接入 Ruff 和渐进类型检查，让规则能够自动验证。

代码审阅时重点检查：规则是否只有一处定义、边界是否校验、状态归属是否清楚、
旧数据是否兼容、验证是否覆盖实际风险。规范服务于这些目标，而不是增加形式要求。
