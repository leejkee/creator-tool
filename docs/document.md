# 文档与文件需求

架构与职责见[架构总览](architecture.md)。本文定义完整图片文档和文件工作流；像素参数由[渲染需求](rendering.md)定义，模块资源由[资源与复用需求](resources.md)定义。

## 完整图片 JSON

| 字段 | 可渲染文档的要求 |
| --- | --- |
| `image-create-tool-version` | 必填，值为 `"v0.2.0"` |
| `documentId` | 必填，非空、非纯空白字符串，表示图片身份 |
| `revision` | 必填，非负安全整数，表示文档内容版本 |
| `composition` | 必填对象，只管理最终输出宽高，具体规则见渲染需求 |
| `modules` | 必填数组，必须且只能有一个根模块；根可为最小内容模块或通过 `layout` 组织子模块的模块 |
| `title`、`sourceNotes` 等 | 可选元数据；保留原值和完整来源内容 |

会话标识、文件路径、工作目录、会话版本、未保存状态和外部变化不属于图片 JSON。保存保留文档内容及扩展数据，不承诺保留原始缩进、键顺序或所有空字段的写法。

扩展元数据内部允许 JSON `null`，不将它当成请求渲染默认值。未经用户要求不增删来源笔记中的结论、条件或推荐。

```json
{
  "image-create-tool-version": "v0.2.0",
  "documentId": "example",
  "revision": 0,
  "composition": {},
  "modules": [
    {
      "id": "root",
      "layout": [1, 1],
      "children": [
        {
          "position": [0, 0],
          "module": {
            "id": "title",
            "type": "text",
            "width": 320,
            "height": 80,
            "text": "图片说明"
          }
        }
      ]
    }
  ]
}
```

## 模块与放置关系

| 项目 | 要求 |
| --- | --- |
| `id` | 必填，非空、非纯空白字符串，在一份图片内唯一；移动、编辑和应用 Style 保留身份 |
| `type` | 最小内容模块必填，取值为 `"text"`、`"image"`、`"rect"`；通过 `layout` 组织子模块的模块省略此字段，不设置独立组合类型 |
| 叶子 | `text`、`image`、`rect`；必须提供固定 `width`、`height`，不得有 `layout` 或非空 `children`；允许省略或空 `children` |
| 文字内容 | `text` 模块必须提供字符串 `text`；保留完整原文 |
| 子模块布局 | 模块具有 `layout: [行数, 列数]` 即表达组合关系；`children` 可省略或为空，实际图文内容放入最小子模块 |
| 网格尺寸 | 恰好两个整数，每项为 `1～4294967295` |
| 放置记录 | 每条必须有 `position: [行, 列]` 和 `module`，后者为完整子模块 |
| 位置 | 从零开始的非负整数二元组，每项不超过 `4294967295`，必须在直接父容器的网格范围内 |
| 占位 | 每个模块占一个单元格；同一父容器内禁止重复位置，允许空单元格 |
| 嵌套 | 各容器坐标独立，禁止循环包含自身或祖先；不支持跨行跨列 |

所有可选择、可编辑对象都是模块；布局数据没有独立身份。模块只保存自身属性和直接子模块的放置关系。文中“容器”仅指具有 `layout` 的模块，不是额外模块类型。

这是对早期组合类型标记的调整：组合模块移除原 `type: "group"`，保留自身 `id`、`layout`、样式及子模块；最小内容模块保持原有内容类型。旧标记可由文件层保留读写，但不作为有效渲染类型，也不在打开或保存时隐式转换。

位置属于父子放置关系，模块内部不另存位置。子项数组顺序不决定布局；调整顺序不能改变已有坐标。放置记录可含元数据，元数据中的 `id`、`type` 等普通键不作为模块结构解释。

## 读写与渲染的边界

- 文件读写接受能转换为当前文档结构的数据，保留可承载的未知字段；不执行非空、模块类型、ID 唯一性、网格范围、样式等渲染业务校验。
- 读写仍有基本结构要求：文档身份和版本标识为字符串，`revision` 为可表示的非负整数，`composition` 为对象，`modules` 为模块数组，模块有字符串 `id`，`type` 可省略、存在时为字符串，放置记录具有合法形状。网格坐标以非负 32 位整数二元组保存，处理声明采用资源文档规定的数组形状。
- 因此，多根、空根、不支持的格式版本或渲染参数错误可能仍可读写，但必须在渲染前由统一校验拒绝。类型声明不替代运行时校验。
- 支持 UTF-8 JSON 及 UTF-8 BOM。语法或结构无法读取时报告错误，保留已有会话和源文件。
- 不隐式迁移旧 `elements`、旧布局对象、旧处理声明、旧素材字段或旧组合类型标记。兼容取舍由对应需求定义，不猜测替代内容。

## 会话与编辑

- GUI 一次只编辑一份文档，不保留其他文档的未保存草稿，也不创建自动恢复副本。底层可以具有多会话能力，不要求 GUI 同时编辑多份文档。
- TS 保存当前文档的工作副本，新增、删除、修改内容和结构都先修改 TS 数据；不因这些尚未保存的 JSON 编辑调用 Rust 文件 I/O。输入草稿的应用规则见[GUI 交互边界](architecture.md#gui-布局与交互边界)。
- Rust 负责读取、保存基线、文档身份、文件冲突和版本保护；保存时接收 TS 的当前已应用内容。读取素材、扫描目录等明确的文件操作不受“JSON 编辑不落盘”限制。
- 未保存状态依据 TS 当前工作副本与最后加载或保存的基线判断；成功保存后更新基线，失败则保留工作副本和未保存状态。
- Rust 会话版本、文档 `revision` 与 TS 本地编辑的先后状态须区分。使用 Rust 的保存、另存为、重载或关闭能力时，必须针对预期会话版本，过期操作拒绝；未保存的本地编辑不能伪造 Rust 会话版本。
- 前端只使用能够精确表示的非负安全整数版本；超出范围明确报错，不能将舍入版本用于保存。普通编辑保留 `documentId`、格式版本和稳定模块 ID，文档 `revision` 沿用受保护的提交规则，不把渲染请求顺序写入该字段。
- 属性修改保留原始文档中的未知字段和来源内容，不能从界面展示数据重建整份 JSON 而丢失扩展数据。删除属性不能与渲染参数显式 `null` 混用。
- 调整网格和位置可以形成暂时不可渲染的文档。结构编辑必须作为完整操作生效，失败不留下部分修改，不隐式移动或删除其他模块；下文明确的新增扩容及删除子树属于用户主动操作。
- 前端按当前文档及本地编辑的先后状态接纳结果，不能让迟到的文件事件、保存响应或渲染结果回退正在编辑的内容。

## Workspace、启动与文档切换

| 情形 | 已确认行为 |
| --- | --- |
| 首次使用 | 提示选择一个 workspace 目录，集中管理图片文档 |
| 应用级配置 | 记录 workspace 路径和 autosave 开关；不作为图片 JSON 的字段，也不要求 workspace 内具有固定项目清单 |
| 后续启动 | 恢复 workspace 并扫描；不自动打开上次文档，主编辑区保持空白，等待用户选择 |
| 扫描范围 | 只扫描 workspace 的一级子目录；判断该目录是否直接包含 JSON，不递归扫描更深目录 |
| 文档计数与名称 | 一个含 JSON 的一级子目录计为一份文档，左侧显示目录名；包含多个 JSON 也只显示一个管理项 |
| 扫描与打开 | 扫描只形成文档列表，不为列出文档而逐份打开编辑；是否可读写、可渲染在打开及渲染时判断，不能因为内容非法就悄悄丢掉管理项 |
| 点击打开 | 优先选择与目录同名的 JSON；没有同名文件时，只有一个候选就直接打开，有多个候选则让用户选择 |
| 无未保存修改时切换 | 处理完未应用输入后直接切换，不保留跨文档草稿 |
| 有未保存修改时切换 | 提供“保存并切换 / 放弃修改并切换 / 取消”；选择保存后必须保存成功才继续，失败则留在当前文档 |
| 未应用输入 | 先按 GUI 的应用、放弃或取消规则处理，不能在切换时静默丢失，也不能隐式保存尚未应用的输入 |

## GUI 模块结构编辑

| 操作 | 已确认行为 |
| --- | --- |
| 新增入口 | 通过底部信息区域的“新增模块”表单选择模块类型、父模块和行列位置；通过 `layout` 组织子模块的模块不设置额外内容类型 |
| 新增位置越界 | 自动扩展父模块的 `layout` 到足以容纳新模块，保留已有模块的位置 |
| 新增位置已占用 | 提示用户另选位置，阻止本次新增，不覆盖或自动挪动已有模块 |
| 删除模块 | 连同全部后代模块一起删除 |
| 删除根模块 | 允许；`modules` 变为空数组，保留文档身份、来源笔记等信息及 JSON 文件本身，可继续编辑和重新建立根模块 |
| 结构调整 | GUI 需要支持新增、删除和调整父子关系；本地修改按上文 TS 工作副本规则处理 |

拖动跨模块转移及其自适应规则单列在后续待办，不据此增加第一版画布拖放交互。

## 新建与模板复制

1. GUI 用户必须提供名称，在当前 workspace 下创建文档；取消创建不产生文件，不默认使用进程当前目录。
2. 创建 `<workspace>/<名称>/<名称>.json`。目标目录已存在即拒绝，不复用或覆盖；失败不得遗留本次创建的半成品文档。创建成功后该目录进入文档列表。
3. 空白新建具有一个 `layout: [1, 1]` 的空根模块，用户通过新增模块填充内容，不要求立即可出图。新文档具有新身份及 `revision=0`，创建成功后为已保存状态；初始选择规则见[GUI 需求](architecture.md#gui-布局与交互边界)。
4. 模板是已保存的完整图片 JSON。复制后保留内容、节点 ID、来源笔记、结构和扩展字段，赋予新文档身份、`revision=0` 和新名称；模板原件不变。
5. 不同图片可保留相同模块 ID；唯一性只在一份图片内要求。模板复制后独立，不依赖源模板继续存在或后续更新。

workspace 用于管理和并列新建，不等于素材基准目录；素材始终按 JSON 文件所在目录解释。底层独立文件工作流仍可显式选择基础目录，或复用一个已打开会话的基础目录：例如从 `/work/A/A.json` 并列创建 B，得到 `/work/B/B.json`。该底层能力不改变 GUI 使用当前 workspace 的规则。

## 保存与另存为

- 保存分为用户主动保存和下表定义的 autosave，两者使用相同的文件保护。写入前确认磁盘仍为加载或上次保存时的基线，防止覆盖外部变化；单纯写盘不因写盘动作增加文档 `revision`，内容变化遵循提交规则。
- 写入失败保留当前内存、未保存状态和原文件；正常文件系统操作不得留下半写目标。不承诺断电持久化、跨进程互斥或跨进程无竞争覆盖。
- 另存为要求明确选择一个已有目录及文件名；没有 `.json` 后缀时补齐，不自动创建同名子目录。目标已存在即拒绝，包括当前源文件。
- 另存成功保留会话标识，切换文件路径，增加会话版本，生成新文档身份并从 `revision=0` 开始，清除未保存和外部变化状态；原文件保留。失败不切换会话。
- 模板复制和另存为必须保持已有资源指向，不能让同一相对路径误指新目录中的另一张图。可以将已知资源引用改为明确绝对路径；不复制素材、不改写任意扩展元数据、处理参数或来源笔记，也不承诺文档因此可移植。
- 名称不得为空白、带首尾空白、以点结尾、含路径分隔符或控制字符；拒绝 Windows 非法字符及保留设备名。文件操作不得突破用户选定的目标目录。

| 保存情形 | 已确认行为 |
| --- | --- |
| 手动保存 | 只保存 TS 当前已应用的内容；未应用输入不隐式生效 |
| autosave 默认状态 | 关闭，用户可在应用设置中开启 |
| autosave 触发 | 应用修改后开始计时，2 秒没有新的已应用修改时保存；新的应用修改重置等待时间，仅有修改时执行 |
| 未应用输入 | 不启动 autosave，也不进入待保存内容 |
| 新素材 | 复制时机、重名及引用更新只由[资源需求](resources.md#gui-选择与复制素材)定义；素材复制与 JSON 保存均成功后才报告保存成功 |
| 保存失败或冲突 | 提示问题，保留 TS 工作副本和未保存标记，不继续需要保存成功的文档切换或 PNG 导出 |
| 恢复副本 | 不提供；autosave 写入源 JSON，不创建用于重启恢复的未保存副本 |

## 外部变化、重载与关闭

- 已打开文件变化分为修改、丢失、不可读取；修改进一步区分有效候选和解析/身份错误。仅格式变化也属于修改。
- 文件检测先形成外部状态，不覆盖 TS 的本地编辑；自身保存不形成外部候选。文件恢复基线后清除外部状态。
- GUI 检测到可正常读取且身份有效的外部修改时，没有未保存修改和未应用输入则自动重新加载；否则提示用户处理。文件非法、丢失或不可读取时保留当前内容并报告问题，不以空文档替换。
- 检测和读取错误不清空文档。修改文档身份的外部文件不得当作同一图片自动接纳。
- 重载读取执行时的磁盘文件，并校验身份；它不是接受历史候选或自动合并。重载成功保留磁盘 `revision`，增加会话版本并建立新基线。
- 有未保存修改或未应用输入时，重载和关闭必须先处理本地编辑，不能绕过保存或放弃确认。没有强制覆盖或自动合并流程；需要保留本地版本时可以另存为新文件。
- 持续检测应及时反映变化，但具体监听方式和轮询间隔不属于需求。跨进程锁和崩溃恢复不属于当前交付范围。

## 验收条件

使用工作区临时目录及素材副本验证：任意目录打开和重复打开、中文与未知字段往返、版本过期保护、无变化编辑、无效渲染参数仍可保存、新建与另存防覆盖、模板独立、资源指向保持、外部有效/无效修改、文件删除恢复、冲突保存拒绝，以及有未保存内容时的关闭和重载保护。失败不得损坏源文件或丢失当前文档。

GUI 还需覆盖：首次选择与重启仅恢复 workspace、一级扫描和多 JSON 选择、单文档切换的保存/放弃/取消、未应用输入保护、新增扩容与位置占用、删除子树及根模块、TS 编辑期间源 JSON 不被写入、autosave 的开关与计时，以及外部变化在有无本地编辑时的不同处理。此处为后续验收条件，不表示已经执行检查或实现相应功能。
