# PySide6 GUI 模块

状态：第一版已实现于 `image_create_tool/gui.py`，本文件继续作为模块设计依据。总体约束见 [dev.md](dev.md)。GUI 与服务协议以 [PYTHON_SERVICE.md](PYTHON_SERVICE.md) 为准；渲染结果以 [PYTHON_RENDERER.md](PYTHON_RENDERER.md) 为准。本文件只定义界面如何消费协议。

## 1. 职责与依赖

GUI 负责窗口、画布展示、元素选择、拖动、属性输入、素材选择、保存状态与问题展示。用户可在 Agent 退出后独立完成编辑、保存与导出。

GUI 主线程只依赖服务端口和数据类型，不直接执行渲染或写 JSON。服务与渲染分别在单进程内的工作线程运行。选中元素、缩放、滚动和表单输入属于 GUI 状态；文档、文件监听与内存历史由服务线程管理。

Python 应用服务不导入 PySide6。GUI 内的 `ServiceBridge` 订阅普通 Python 服务事件，将它们转为排队的 Qt 信号；服务回调可以来自后台线程，桥接回调只投递信号，不直接更新控件。窗口、控件和 `QPixmap` 的创建与更新都在 GUI 主线程进行。

## 2. 窗口与画布

入口提供“打开工作目录”，使用目录选择对话框，服务负责读取根目录的 `pjt.json` 并识别项目。空项目显示空画布及默认目录配置。项目设置提供素材目录与输出目录选择，初始值分别为工作目录下的 `assets/`、`outputs/`，可以改为其他目录；GUI 只提交配置，服务负责路径解析与保存。

采用 Qt Widgets：`QMainWindow` 组织窗口，`QSplitter` 组织三栏，`QGraphicsView/QGraphicsScene` 展示渲染图与交互覆盖层。模块和元素使用列表/树控件，右侧使用属性表单。

```text
项目名称   保存状态   撤销 / 重做                 导出 PNG
┌────────────┬─────────────────────┬─────────────────┐
│ 模块列表   │                     │ 当前选择属性    │
│ 添加/复制  │     可缩放画布      │ 文字 / 素材     │
│ 拖动排序   │                     │ 大小 / 样式     │
│ 元素树     │ 选中框与拖动手柄    │ 间距 / 位置偏移 │
└────────────┴─────────────────────┴─────────────────┘
问题列表：缺素材、字体缺失、内容溢出、渲染错误
```

- 可选择模块，也可选择其中的图片、文字等子元素。重叠对象可以通过元素树选择。
- Qt 只展示渲染结果，攻略文字不在 Qt 中重新排版。元素树来自文档，命中区域来自渲染布局结果。
- 场景坐标对应导出画布的逻辑像素；鼠标坐标使用视图变换映射，缩放不修改文档。
- GUI 只同时使用同一 `renderId` 对应的图片与布局；边界过期时显示“更新中”，不允许基于旧边界开始新的拖动，文字属性编辑仍可继续。
- 画布展示选中框、拖动手柄和层级命中区域；拖动过程只更新交互覆盖层，松手后提交位置操作。可额外提供临时视觉反馈，但不能把它保存为正式渲染结果。

## 3. 编辑能力

- 模块添加、复制、删除和重排；元素文字编辑、素材替换、样式修改、拖动与尺寸修改。
- 自动布局元素拖动提交 `offsetX/offsetY`，提供“重置位置偏移”。固定布局显式提交 `x/y/width/height`。
- 文案在属性面板编辑，首版不要求画布内直接输入。连续输入短暂合并，拖动在松手时形成一次操作。
- 合成属性包含宽度、自动/固定高度、背景、外边距及模块间距；模块属性包含布局方向、内边距、元素间距及背景。
- 图片属性包含显示框、原图像素裁剪与填充方式，默认 `contain`；用户选择 `cover` 或裁剪时展示实际可见范围，不覆盖原图。
- 撤销/重做调用服务命令，不维护另一套 GUI 文档历史。
- 素材对话框调用服务搜索，展示候选和缩略图；导入通过文件对话框取得外部路径，再交给服务复制入项目。

## 4. GUI → 服务

通过服务端口提交异步命令，返回 `Future[CommandResult]`，GUI 不在主线程调用阻塞的 `result()`。命令结果携带请求 ID，用于对应具体输入；错误按结构化字段展示。

编辑提交包括 `documentId`、`baseRevision` 与操作列表。服务成功提交后，GUI 使用返回的文档版本更新视图；GUI 的临时输入不会直接修改服务快照。冲突时保留用户未提交输入并重新读取文档，不盲目重放或覆盖。

存在外部候选时，编辑仅提交到服务的当前内存状态，界面明确显示“外部修改待处理，尚未写回”；不把命令成功误认为文件已保存。

服务拒绝操作或保存失败时，显示失败原因并保留未提交输入，不显示“已保存”。删除选中元素后清理相应选择状态。

服务保存期间短暂阻止外部普通写入；获取保护失败时 GUI 显示“文件被其他程序占用，修改尚未保存”，提供重试，不冻结主线程。平时不持有该保护，不要求用户关闭应用才能让 Agent 编辑。已有外部候选仍由用户审阅，不因 GUI 优先而自动覆盖。

导出顺序：

1. 将正在输入或拖动的修改提交；若存在外部候选，先完成合并/恢复并等待写回成功。
2. 使用文件保存对话框取得输出路径，初始目录为项目配置的 `outputsDir`，取消则不创建任务。单次选择其他位置不自动改写默认输出目录。
3. 请求导出刚提交成功的版本，立即显示任务状态。
4. 收到成功结果后提供打开图片/所在目录入口；若文档已更新，标明导出属于之前的版本。

## 5. 服务 → GUI

消费 `document_changed`、`job_changed`、`preview_ready`、`export_ready`、`assets_changed`、`external_change_pending/invalid/resolved` 与 `service_error` 事件。字段及事件顺序见服务文档。

收到预览后按 `target` 区分当前图、外部候选和合并预览，再核对版本、候选 ID、内容指纹与渲染 ID。外部预览使用独立标签，不替换当前编辑状态；新一轮未提交输入存在时保留提示。

GUI 用不可变 PNG 字节构造展示图，释放旧图像引用。同进程不需要共享内存句柄；`QPixmap` 与控件更新在主线程完成。

关闭前处理外部候选和未落盘修改，选择保存、明确放弃或取消关闭。取消订阅后忽略迟到通知，服务负责协作停止线程；GUI 不在主线程阻塞等待线程结束。撤销历史仅在内存，退出后清空。

## 6. 外部文件变化审阅

服务监听唯一 JSON，发现外部修改后通知 GUI。GUI 展示变化摘要，并允许切换当前内容、外部候选和待合并内容的预览；原始 JSON 解析失败时显示错误并保留当前图。

- “合并”：调用服务生成字段差异，不冲突修改可合并；同字段修改、删除/修改及顺序冲突由用户逐项选择，确认后写回同一文件。
- “恢复当前内容”：拒绝外部修改，把当前 GUI 内容写回文件，保留已有微调。
- “暂不处理”：保留候选并暂停自动写回；当前内容可以继续在内存编辑，但必须明确未保存状态。

外部再次变化或用户继续编辑后，旧合并方案失效，重新生成差异与预览。GUI 提交选择时带候选 ID、当前版本和文件指纹；服务拒绝过期选择后重新展示，不静默应用。

## 7. 独立验收

- 使用假的服务端口和固定图片/布局，无需真实渲染线程即可验证交互。
- 后台线程事件不会直接更新控件，主线程不等待耗时任务。
- 连续修改与旧任务乱序完成时，图片及边界仍保持同版本。
- 保存失败、版本冲突与渲染失败不会丢掉表单输入，也不会伪装成保存或导出成功。
- 关闭文档后迟到结果不进入另一个文档。
- 外部候选审阅、冲突取值、恢复及延后处理有明确状态；候选图不会冒充当前图。
